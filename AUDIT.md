# Аудит Password — 24 октября 2026

## Что делает репозиторий

Это клиентское демо ввода одноразового кода для mishanaer.com/ui. Пользователь выбирает 4/5/6 цифр, скорость анимации и тему; проверка кода имитируется локально за 2 секунды. Рассмотренная нагрузка — независимые посетители статической страницы: базы данных, серверной проверки, пользовательских аккаунтов и общей очереди нет.

Аудит выполнен по ponytail-audit. Ниже отделены найденные проблемы от исправлений, выполненных по отдельному запросу на очистку и публикацию. Исходная точка сравнения — рабочая адаптация Smintfy/ui-snippet до выделения этого репозитория.

## Обязательно исправить

### 1. Уязвимые зависимости — исправлено перед публикацией

- **Что это:** Next.js собирает и обслуживает страницу; PostCSS обрабатывает стили. Места: `package.json:18`, `package.json:44`, `package-lock.json`.
- **Проблема:** исходный lock-файл давал 15 предупреждений npm audit, включая критический уровень у Next.js 15.2.6. Одно обновление до Next.js 15.5.28 оставляло вложенный PostCSS 8.4.31 с известными проблемами обработки недоверенных CSS/source maps.
- **Исправление:** Next.js и eslint-config-next обновлены до 15.5.28, React/React DOM — до 19.3.1. Для PostCSS Next.js закреплён override 8.5.31. Lock-файл пересоздан и проверен через чистый `npm ci`; `npm audit` возвращает 0 уязвимостей. Совместимость override подтверждена production-сборкой.
- **Если пропустить:** установка возвращает известные уязвимые пакеты. Не все опубликованные сценарии применимы к этому статическому демо; отсутствие предупреждений npm также не означает отсутствие любых возможных уязвимостей.

Источники предупреждений: [Next.js](https://github.com/advisories/GHSA-w37m-7fhw-fmv9), [PostCSS](https://github.com/advisories/GHSA-6g55-p6wh-862q).

## Следует исправить

### 2. На 320 px ряд из шести ячеек сдвигался вправо — исправлено

- **Что это:** ограничение ширины формы в `components/password.tsx:134`.
- **Проблема:** `max-w-full` сжимал контейнер ряда с 256 до 236 px, но абсолютные позиции ячеек оставались прежними. Фактический центр ряда был на 10 px правее центра превью.
- **Исправление:** удалено ограничение `max-w-full`. Ширина ряда определяется содержимым; размеры ячеек 36×40 px сохранены. Также отключено служебное расширение невидимого input на 40 px (`pushPasswordManagerStrategy="none"`), иначе после центрирования оно создавало горизонтальную прокрутку на 320 px.
- **Если пропустить:** на узком экране отступы по бокам визуально различаются.

### 3. В проекте оставались неиспользуемые демо и зависимости — удалено

- **Что это:** бывшие `app/[snippet]`, `components/sections`, `components/ui`, три посторонних snippet-компонента, Select/Slider и их helpers, старые hooks, public-изображения и настройки git hooks/форматирования.
- **Проблема:** эти файлы не нужны OTP, но расширяли публичный репозиторий, набор маршрутов и установку. Кроме того, существовали два одинаковых `cn` helper и отдельная обёртка ThemeProvider без собственной логики.
- **Исправление:** граф импортов построен от обеих страниц и layout, включая CSS и type-only импорты. Оставлены OTP, playground, используемый Button и необходимые shared helpers/tokens. Тип иконки сохранён без неиспользуемого реестра иконок. Объединён `cn`, провайдер темы включён прямо в layout, удалён пустой next.config. Shared Button не получил локальных визуальных вариантов.
- **Если пропустить:** поддерживать и обновлять пришлось бы код, который не участвует в демо.

Удалены 9 прямых зависимостей: `@number-flow/react`, `@radix-ui/react-visually-hidden`, `radix-ui`, `sonner`, `lucide-react`, `lint-staged`, `prettier`, `prettier-plugin-sort-imports`, `prettier-plugin-tailwindcss`. Исходники TS/TSX/CSS/JS: 54 → 20 файлов, 7086 → 1477 строк; сгенерированные файлы и документация в этот подсчёт не входят. Общие токены и API необходимых примитивов сохранены для совместимости с дизайн-системой.

### 4. Отмена проверки пока защищена только ручными сценариями — осталось

- **Что это:** таймер и редактирование в `components/password.tsx:97`, `:112`, `:159`; скрипты проверок в `package.json:5`.
- **Проблема:** автоматического регрессионного теста нет. Проверки типов и линтер не обнаружат возврат ошибки, при которой после изменения цифры результат относится к старому коду.
- **Исправление:** добавить один регрессионный тест с управляемыми часами: начать проверку правильного кода, заменить цифру до завершения, убедиться, что старый результат не срабатывает, а новый определяется через полные 2 секунды. Тем же тестом покрыть отмену при неполном коде и смене длины.
- **Если пропустить:** будущая правка может вернуть ошибку, которая уже воспроизводилась ранее. Сейчас эти ветки проверены в браузере; новый тестовый стек в рамках удаления лишнего не добавлялся.

## Сохранённые решения и границы применения

- Это демо: коды `1234`, `12345`, `123456` находятся в клиентском коде. Они не являются секретами. Для настоящего входа нужна отдельная серверная проверка; этот репозиторий её не обещает.
- Постоянные видимые сообщения успеха и ошибки убраны по решению владельца. После завершения анимации результаты визуально одинаковы; текст остаётся в live region для скринридера. Это ограничение минимального превью, не готовая обратная связь для реального входа.
- Движение, отскок 0.15, размеры, скругление 12 px и тайминги оставлены согласованными. Полного отдельного режима reduced motion нет; accessibility-аудит не выдавался.
- Лицензии Smintfy, Richbox и исходных примитивов сохранены. Источники и изменения shared-кода описаны в `components/richbox/README.md`.
